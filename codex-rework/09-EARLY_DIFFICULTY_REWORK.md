# 09 - 提升前期關卡難度 (Early Difficulty Rework)

## 1. 核心目標
玩家反映目前的體驗是「要從第一關 (S01) 就要有難度」。
目前的設計中，第一關的難度參數（如 Boss 血量/傷害倍率、基礎雜兵數量）非常低（例如 S01 的 BossScale 僅有約 0.43，且雜兵數量較少），這讓前期過於無腦，缺乏刺激感。
本次重構旨在**大幅提升 S01~S04 早期關卡的基礎壓力**，讓遊戲一開始就具備挑戰性，同時縮小前後期關卡的難度落差，讓整體難度曲線從「低起點、陡峭爬升」改為「中高起點、平穩爬升」。

---

## 2. 實作規格與範圍

### A. 提升早期 Boss 與精英怪強度 (`src/data/progression.ts`)
* 找到 `bossScale` 的計算公式：
  * 目前主線的 `bossScale` 大約是 `Math.min(1.3, .35 + rank * .08)`。
  * **請修改為**：起點更高、爬升更平穩。例如 `Math.min(1.3, 0.65 + rank * 0.05)`，確保 S01 的 Boss 倍率從 0.43 直接拉升到 0.7 左右，第一關的 Boss 就不再是隨便打都能死的木樁。

### B. 提升早期基礎雜兵海數量 (`src/data/progression.ts`)
* 找到計算波次敵人數量的 `base` 變數：
  * 目前是 `const base = side ? 14 + rank : 12 + Math.floor(rank * .6);`
  * **請修改為**：讓早期關卡一開始就有壓迫感。例如改為 `const base = side ? 18 + rank : 18 + Math.floor(rank * 0.4);`，讓 S01 的起手雜兵量提高 50% 左右。

### C. 平衡修正
* 由於我們提高了 S01 等早期關卡的壓力，如果 `test:simulation` 中的 `easy` 模式 S01 測試因此失敗（HP 歸零），請適度微調上述參數，確保 AI 測試剛好能以低血量驚險過關，而不會出現絕對死局。
* 同樣不得破壞技能樹既有強度與 `test:simulation:free` 的勝利結果。

---

## 3. 驗證標準
* 執行 `npm run test:simulation`：S01~S12 的所有難度依然能顯示 `victory`，但觀察輸出時，S01 的剩餘防線 HP 應明顯比以前低（防線損失變大），代表難度確實提升。
* 執行 `npm run test:rules` 確保無語法與規則錯誤。
