# 星際夏日：招募、屬性與章節

內容版本：0.4.0-dev.1。這份文件是本版規格；未變動的局內自由配點沿用 0.3。實作以本次已討論的免費、不可刷資源、只有玩家攻擊敵人的弱點系統為範圍。

## 可玩內容

- 初始六位角色原裝免費開放；新增汐音 C07、熾夏 C08。
- 八位角色各有原裝與星際夏日裝，共 16 個可用形態。新角色的兩套分開取得。
- 同一角色最多一個編隊位置；每隊 1–5 人、一名隊長。只能在戰鬥外選擇已持有形態，戰局快照固定裝備。
- 18 條角色技能樹＋1 條共用樹，共 186 節點、29 終極。沿用每 60 XP 得 2 點、每局 24 點、每人一終極、全隊三終極。
- 四章、12 個主線關卡，另有三個夏日支線關卡。每關有前後劇情、八波敵群、固定種子的事件／變體與首領。

## 免費獎池與一次性收入

常駐混合池含八套夏日裝、汐音原裝、熾夏原裝，共 10 項；每項機率 10%。沒有付費抽、廣告抽、體力、每日任務、刷關點數或升星。

| 來源 | 數量 | 首次獎勵 | 總收入 |
| --- | ---: | --- | --- |
| 12 主線＋3 夏日支線 | 15 | 1 張招募券 | 15 券 |
| 每個主線的四人／禁隊長技能／兩終極挑戰 | 36 | 25 招募點數 | 900 點 |
| 51 個目標全完成 | 1 次 | 直接補齊本期所有未持有形態 | 不依賴抽獎運氣 |

1 券或 100 點抽一次，優先消耗券；總收入相當於 24 抽，並非單靠 24 抽隨機結果必然全收集；全目標保底觸發後會停止抽獎，未使用資源保留，不要求用完。沒有額外自選夏日裝贈送。

精確重複「同一形態」轉為 10 共鳴碎片；100 碎片可指定一個本期未持有形態。抽到新角色夏日裝即可使用該角色夏日形態，不會附送原裝。持有原裝後抽到夏日裝也不是重複。

全收集後停用抽獎與兌換，保留所有未花費券、點數與碎片。未承諾將來池子的通用規則。新收藏不提供全隊加成；所有技能樹仍是每局重新配置。

## 單向屬性弱點

五種攻擊屬性：動能、電漿、電弧、熱能、重力。每種敵人只有一種固定弱點；相符 ×1.5，其他 ×1，不設抗性減傷，也沒有角色防禦屬性。

| 敵人 | 弱點 |
| --- | --- |
| E01、E06、B01 | 熱能 |
| E02、E08 | 重力 |
| E03、E07 | 動能 |
| E04、B02 | 電弧 |
| E05、B03 | 電漿 |

所有角色歸屬傷害——普通攻擊、隊長傷害、衍生彈體、反射、持續區域與 DoT——依出戰形態決定屬性。弱點倍率只套用一次，再進入既有護盾、破盾、護甲及曝露計算。控場時間、位移及護盾不吃弱點倍率。

敵人頭上顯示弱點符號；情報、圖鑑與戰鬥角色列顯示文字／符號，並非只靠顏色。傷害與持續傷害顏色依實際屬性，持續傷害名稱也隨之改變。

## 兩位新角色

汐音：遠程地雷工程師，原裝動能。自動部署有限數量的感應地雷，短暫啟動後偵測敵人，等待可蓄能。以目標預測位置部署，靜止砲台與首領也可命中；過期清除，上限不會無限成長。隊長技能連鎖引爆所有現存地雷，無雷時不能施放，不消耗冷卻。兩樹偏向密集雷網／蓄能對甲。

熾夏：中程過熱機槍手，原裝熱能。射擊累積熱量並提高傷害；熱量到 100% 強制停火散熱，冷卻到零恢復。隊長技能立即排熱並短暫提高射速；兩樹偏向高熱輸出／散熱循環。熱量、冷卻、排熱加速期限、地雷位置與蓄能全部存入完整戰局快照。

兩人沿用正常 XP 與正式配點。新樹的全部節點與前置見 [186 節點表](FREE_SKILL_NODES.md)。

## 存檔與防刷邊界

IndexedDB 同一筆存檔包含進度、收藏、資源、已領目標、完整戰局與最近抽獎結果。招募／兌換／換裝以 readwrite 交易檢查 revision，產生結果並一併扣款，交易成功後才顯示結果。UI 忙碌鎖防雙擊；sequence 檢查避免排隊中的舊自動存檔覆蓋已完成招募。

目標鍵固定為關卡／挑戰，不使用隊伍或種子作為新獎勵鍵。重打、換隊、失敗、重載與再次結算不重複發獎；多分頁衝突要求讀取最新資料。進行中戰局必須先完成或放棄，才能招募、兌換或換裝。

舊存檔遷移只新增收藏結構、補記已完成目標的首次獎勵；不重置既有進度。0.1、0.2、0.3 戰局維持各自戰鬥規則，新開局才採 0.4。拒絕儲存時仍可暫時試玩，但不能假裝完成招募保存。

這是本機防重複領取，不是伺服器防作弊。手動修改 IndexedDB、清除網站資料、換瀏覽器與換網址來源不在防刷保證內；沒有雲端帳號或跨裝置同步。

## 驗證

以下完整驗收為舞台雙角色造型更新前的基礎版本結果；本次素材修訂的針對性驗證另見本節末尾，未將歷史全套測試當成本次全部重跑。

可重現指令：

```sh
npm run typecheck

npm run test:simulation:free
E2E_PORT=5174 npm run test:e2e
npm run build
npm run test:assets
# 5173 上運行正式 preview 後：
npm run test:production
```

已完成的模擬：初始角色原裝覆蓋 51 個目標 × 3 種子，153/153 通關；10 個獎池形態最終關代表構築 10/10；29 終極 × 兩種投入 × 前三關 × 10 種子，1,740/1,740 通關，58 次完整命令重播一致。每局在第 7 點配點後驗證存檔恢復。這些是固定政策的可行性證據，不是任意編隊均平衡或完整隨機勝率估計。

正式版 Chromium 模擬 390×844、10 Mbps／100 ms RTT，無開發測試入口：首頁可操作約 0.70 秒，首場戰鬥約 3.38 秒；以真實等待、正常 UI 配點、3× 自動技能與重載驗證，無 console error 或失敗請求。詳細數據見 [production/smoke.json](../artifacts/validation/0.4.0-dev.1/production/smoke.json)。

最終工程驗證：型別檢查與正式 build 通過；規則／存檔 282/282 通過。Chromium／WebKit 共 162 個功能案例通過，另有三個 Chromium 效能案例通過；合併為 165 通過、三個 WebKit 效能案例依桌面量測政策略過。服裝修正後再跑十個招募／換裝案例，全數通過，包含 320–1440 px 畫面、先取得夏日裝、雙擊防重抽與戰局恢復。

60 秒、3×、120 敵人／400 敵彈／12 區域的獨立高密度測試：p95 幀時間 26.9 ms（門檻 33.3 ms），模擬約 90 ticks/s，無錯誤。先前與功能測試同時執行的 37.3 ms 未通過報告保留在 performance/，未放寬門檻；以 performance-recheck/ 的獨立重測取代該案例。這是桌面 Chromium／SwiftShader 的合成壓力場景，不是真實手機效能保證。
