# 從第一關開始的加壓版

本地內容版本：`0.6.0-dev.2`，關卡平衡版本：`4`。尚未部署；正式版仍為 `0.6.0-dev.1`／平衡版本 `3`。

## 設定

套用於簡單、困難、支線、限制挑戰與百波的新戰局。一般波次的生命與護盾乘以 1.25、攻擊傷害乘以 1.8、波次與組內進場時間乘以 0.75。

同一敵種、同一編成的參數壓力指標為 `生命 × 傷害 ÷ 進場間隔`，因此相對 v3 為 `1.25 × 1.8 ÷ 0.75 = 3`。這是可重現的設計指標，並不表示實測勝率、失血或主觀難度精確變成三倍；技能的聚怪收益、護盾、控制與取得時機都會改變實際結果。

- 主線／支線波次間隔：25 → 18.75 秒；百波：20 → 15 秒。遊戲預告使用同一份排程。
- S01 第一波改成混合編隊，包含快敵、重裝與砲手；S01～S03 不再沿用前兩波教學編排。
- 保留每四波或百波每十波內的疏散編成。首領在常規波次排程結束後保留 15 秒間隙；百波首領仍於第 100 波出場。
- S01 首領傷害額外乘以 2，以避免密集敵群讓聚怪構築獲益後，第一關反而變容易。其他首領與主線入口護衛保留 v3 數值；所有首領保留完整技能預警。常規波次遠程攻擊在發射時套用傷害增幅，命中時不重複計算。
- S03 簡單是首個精英關卡，重裝／重型精英／突進精英的編成權重另乘 0.4／0.2／0.4，空出的名額由其他允許的敵種分配。這是權重調整，不是直接按比例減少總敵人數。它避免尚未建立構築前的連續重裝堆積。
- 關卡數、波次數、總敵人數、總經驗與技能點保持原值。沒有新增敵種、技能或永久成長要求。

## 相容性

新開局預設 v4；舊內容 `0.6.0-dev.1` 仍預設 v3。存檔恢復使用各自保存的版本，不以目前版本覆寫。66 組 v3 戰局在 120 tick 的完整狀態雜湊均與修改前相同，恢復後的後續模擬也一致。v1／v2 相容測試保留。

## 驗證與限制

執行：

```sh
npm run build
npm run test:rules
npm run test:offline:unit
node --import tsx scripts/validate-assault-balance.ts --output=artifacts/validation/assault-v4/final
E2E_PORT=5194 npx playwright test tests/e2e/assault-balance.spec.ts
```

配對測試對同一原裝隊伍、同一配點策略與種子比較 v3／v4。S01～S03 簡單使用 20 個調整種子，以及最終才使用的 10 個驗證種子（S01 從 110101 起，S02／S03 從 90101 起，均每次加 113）；其餘全部模式使用一個種子作基本檢查。四種配置涵蓋兩種米菈擊退隊伍、雷娜磁荷、芙蕾侵蝕與護盾，合計 1,232 次戰局。

逐局結果、平均失血、通關次數、敵人峰值與剩餘耐久保存在 `artifacts/validation/assault-v4/final/runs.json` 和 `summary.json`，簡明彙整另存 `report.md`。它們是固定策略的比較，不是最佳玩家策略的證明；其他模式的單一種子不能證明每關都有穩定可行解。

644 項規則／存檔測試、24 項離線單元測試與 Chromium／WebKit 首關畫面檢查通過。大量敵人驗證採桌面 Chromium 的手機尺寸、120 個持續存活目標，不能代替實體手機測試。

困難／限制挑戰／百波仍需更完整的通關與角色選擇偏差評估。不得將參數壓力三倍或測試執行完畢，描述為全模式平衡驗收通過。
