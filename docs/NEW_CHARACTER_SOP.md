# 新增角色 SOP

這是新增角色的工作入口。先填寫 [角色規格模板](templates/CHARACTER_BRIEF.md)，再依序完成玩法、美術、接入與驗收。動畫尺寸與打包方法沿用 [角色素材製作 SOP](CHARACTER_PRODUCTION_SOP.md)，畫風沿用 [角色畫風基準](CHARACTER_ART_DIRECTION.md)。新增造型沿用角色 ID；只有新角色才新增角色 ID。

## 1. 定義身份與玩法

記錄姓名、成年年齡、身世、加入小隊的原因、與既有角色的關係、髮型服裝、武器、定位及弱點。用一句話描述玩家選她出戰的理由，不能只寫「傷害更高」。

列出普攻的索敵、射程、彈道／部署、命中、冷卻、資源循環；隊長技能的施放條件、作用範圍、持續時間、冷卻與空放規則。技能描述、實際模擬與畫面必須對得上。特殊資源須讓玩家看見，例如地雷數量、蓄能進度、熱量與停火狀態。

## 2. 先做技能差異檢查

找出最相似的既有角色，比較普攻、隊長技能及每條技能樹。至少說明兩項會改變出戰選擇或操作時機的機制差異，以及一項不用讀名字也能辨認的視覺差異。換色、改技能名、增加傷害或改射速，不能單獨當作新玩法。

| 既有核心玩法 | 比較時要保留的界線 |
| --- | --- |
| 璃音：彈道、多目標與破盾 | 與熱量型連射區分射擊節奏和資源管理 |
| 雷娜：跳躍連鎖、磁荷引爆 | 連鎖必須看得到各跳目標，不只是範圍圓圈 |
| 凜月：重型優先、長線貫穿 | 與一般破甲彈區分索敵與狙擊窗口 |
| 米菈：緩速、聚怪、擊退 | 改變敵群位置與停留時間，不能只有爆炸傷害 |
| 芙蕾：拋射、燃燒、延遲爆炸 | 與陷阱區分落點、等待時間及觸發方式 |
| 希雅：無人機、曝露協同、護盾 | 分清自身輸出、全隊增益與防線保護 |
| 汐音：預置地雷、蓄能、手動引爆 | 必須在實戰看得到預置與等待的價值 |
| 熾夏：升溫連射、過熱停火、排熱 | 必須看得到熱量循環與排熱的時機選擇 |

普通節點可以提供數值成長；終極必須有明確的構築結果，並寫出攻擊行為或戰術選擇如何改變。用固定靶確認程式效果，再用真實移動敵群確認差異是否仍存在；不能只看文案判定不雷同。

## 3. 製作完整美術組

每套造型都要交付：成年立繪、角色卡專用背景、Q 版六格動畫、武器辨識及攻擊特效／音效。先確認身份，再生成人物，最後在實際介面縮小檢查。

- **背景品質以原本 C01／C02 立繪為基準。** 必須有插畫細節、前中後景深度、材質、主光／輪廓光與角色所屬世界的氛圍；單純漸層、網格、幾何圓環或紋章不能作為完成稿。
- **不用關卡地圖充當立繪背景。** 製作角色卡專用的人物視角插畫，避免俯視戰場、中央長道路及巨大人物站在縮小建築上的錯誤比例。人物與背景可以分層，最終須像同一張完整立繪；場景敘事集中兩側，頭臉與武器位置保持清楚。現有完整背景立繪不因新增角色而自動重畫。
- 原裝背景呼應職能，主題裝保持同一遊戲世界的畫風與光影。此次原裝採汐音的海港工兵基地、熾夏的武裝機庫；夏日採科幻海岸城市露台。同系列可共用背景，但需逐一檢查人物色溫、構圖、裁切與可讀性，不可只驗一人。
- Q 版約 2.5 頭身；六格為待機、準備、瞄準、攻擊、後座、回復。依武器設計動作，不能拿立繪縮小、鏡像或晃動代替。
- 同人物不同造型保持身份，但重新設計服裝與姿勢。長武器不得讓整個人物被縮得特別小。
- 洋紅是製作去背用色，不是角色輪廓。檢查髮絲、衣角、透明配件及武器的紫邊；在深底、淺底與實際角色卡上檢視。去背不能把真正的紫髮、服裝或電弧刪掉；原圖有污染時回到素材製作階段修正。
- 保存完整提示詞、參考、來源、修改紀錄、正式版本檔名與 manifest；不可只留下個人暫存路徑。

## 4. 程式接入清單

| 接入項目 | 檔案與檢查重點 |
| --- | --- |
| ID、狀態與相容性 | `src/sim/types.ts`、`src/sim/engine.ts`：新 ID、特殊資源初始化、保存／還原驗證；評估內容版本與舊局處理 |
| 人物與造型 | `src/data/content.ts`、`src/data/forms.ts`：描述、武器、被動、技能、造型屬性、立繪、`formBackdrop`、`formMotion` |
| 技能樹 | `src/data/deep-trees.ts`、`src/sim/deep-tree.ts`：前置、分支、終極、mod 聚合與存檔驗證 |
| 真實攻擊 | `src/sim/deep-weapons.ts`、`src/sim/special-weapons.ts`、`src/sim/weapons.ts`、`src/sim/range.ts`：索敵、命中、射程、冷卻、特殊資源與隊長技能 |
| 動畫與 VFX | `src/data/character-motion.ts`、`src/game/actors.ts`、`src/game/scene.ts`、`src/game/effects.ts`、`src/game/skill-effects.ts`、`src/game/audio.ts` |
| 圖片與背景 | `src/ui/app.ts`、`src/ui/portrait.css`、`src/game/chroma.ts`：共用立繪流程、專用底紋、去背與邊緣清理 |
| 取得及 UI | `src/storage/collection.ts`、`src/ui/collection.ts`、`src/ui/roster.ts`、`src/ui/format.ts`：解鎖、換裝、定位標籤、未招募狀態；檢查固定人數／獎池分母 |
| 隊長操作 | `src/ui/auto-tactical.ts`、`src/ui/battle.ts`：可施放條件、自動施放、禁用原因、資源顯示與實際模擬一致 |

這是定位入口，不代表只改這些檔案即可完成。以 `rg` 搜尋最相近角色 ID、角色總數及獎池數量，檢查其他寫死清單；不可把歷史版本的人數或規則一律取代。不要把未取得的新角色自動送進舊存檔。

傷害由模擬事件決定，畫面只表達事件：槍口跟隨出戰位置與朝向；地雷、爆炸、連鎖及大招落點取自實際作用位置。不能用固定位置的假爆炸充當真實命中。暫停時動畫與特殊資源停止，恢復和 3× 不得重播已結算傷害。

## 5. 驗收順序

1. **資料完整：** 所有新造型的立繪、背景設定、六格、武器掛點、manifest 齊全。先擴充驗證清單再執行，不能只跑原八人案例。
2. **機制驗證：** 測普攻、隊長技能、前置節點、終極、特殊資源邊界、無目標、空資源、Boss、護盾、裝甲與保存／還原。測試應驗證行為結果，不能只斷言資料裡寫了某個數值。
3. **畫面驗證：** 原裝／主題裝、已招募／未招募、編隊、詳情、招募、換裝、戰鬥、隊長演出；確認背景、無紫邊、無裁切、人物比例及攻擊辨識。
   背景另須和 C01／C02 原版卡片並排比較：細節密度與完成度相近、視角與人物尺寸協調、前景人物清楚、沒有以關卡地圖或簡單底紋替代插畫。確認縮小到手機卡片仍有層次，而不是只在大圖中好看。
4. **操作驗證：** 暫停／續玩、1×／3×、鍵盤與觸控、先預覽再裝備；預覽不能改收藏或扣資源。
5. **實戰比較：** 相同關卡、種子、隊伍與技能點預算，替換最相似角色；記錄清群、精英／Boss、漏怪、防線及技能時機，檢查角色是否互有適用情境。高血量靶不能替代關卡測試。
6. **尺寸與瀏覽器：** Chromium／WebKit；至少 390×844，並覆蓋 320、768、1024、1440 寬度。存手機與桌面截圖、攻擊影片及測試報告；真機未測就明列未測。

```sh
npm run test:rules
npm run build
npm run test:assets
E2E_PORT=5174 npx playwright test tests/e2e/form-motion.spec.ts tests/e2e/roster-overview.spec.ts tests/e2e/collection.spec.ts
```

`build` 已包含型別與動畫素材檢查；瀏覽器 port 要與使用中的本地開發服務一致。依新增機制再執行對應的模擬與測試，以上通過不等於平衡與真人體驗已通過。

## 6. 完成與交付

交付角色規格、素材來源、修改檔案、實際驗證結果、畫面／影片，以及未完成項目。明確區分「本地完成」、「已建置」與「已部署」，不能把本地結果當成線上更新。

目前的製作缺口須保留追蹤：汐音的預置價值、地雷大招裝飾落點，以及熾夏與璃音的彈道辨識仍需各自實作和驗證。本 SOP 是後續完成標準，不代表這些玩法已改善。
