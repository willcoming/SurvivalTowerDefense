# 手機遊戲介面更新

本次調整手機顯示與操作方式，戰局內容版本沿用 `0.4.0-dev.1`。

## 操作方式

- 全螢幕遊戲面板，上方顯示遊戲狀態，下方功能列切換作戰、編隊、招募、圖鑑與紀錄。
- 作戰中心按章節切換關卡；編隊一屏顯示全部八位隊員，包含未招募角色。上方顯示「已招募 X / 8」與「出戰 Y / 上限」，出戰名單及出擊操作保持可見。
- 隊員卡片標示「已出戰／待命／未招募」、持有造型數與可換裝狀態。點卡片開啟角色面板，查看能力、加入／移出小隊及指定隊長；人數已滿時先移出一人再加入。
- 造型面板列出角色的全部造型。點選只預覽立繪、攻擊屬性與能力，按「裝備」才套用並儲存；未持有項目顯示鎖定與取得方式。有進行中的行動或處於暫時試玩時不能裝備。
- 圖鑑角色、章節與收藏可以用左右按鈕切換，也可直接從選單選取。
- 圖鑑、服裝能力、戰鬥報告、敵方對策與完整立繪放進詳細面板。只有面板內容需要捲動，關閉按鈕保持可見。
- 本局技能樹以完整路線圖顯示目前角色的分支、前置連線與終極節點，使用不同標記區分已取得、可解鎖和待解鎖。一般直式手機一屏看完整棵樹；短視窗只捲動路線圖，角色、路線與確認操作保持固定。點節點預覽，確認後才花點。完整效果與前置條件由「效果／前置」查看。
- 招募與收藏兌換、音效與存檔管理分開切換；招募或兌換完成後直接顯示已保存結果。
- 螢幕較矮時縮減裝飾與立繪預覽，保留主要操作的點擊空間。桌面寬度超過 800px 時恢復完整資訊排列。

## 結構

`mobile-controls.ts` 管理分頁與原生詳細面板；`mobile.ts` 處理首頁、編隊說明與圖鑑；`roster.ts` 與 `roster.css` 呈現八人總覽、角色面板及造型預覽。`mobile-secondary.ts` 處理其他選單；`mobile-combat.ts` 處理戰鬥覆蓋面板，`tactical-tree.ts` 與 `tactical-tree.css` 處理完整技能路線圖與遊戲風格；`mobile-notice.ts` 將存檔等通知放入頂部 HUD，保留完整恢復操作。`mobile-game.css` 統一場景、立繪、金色選中狀態與珊瑚色出擊按鈕。

編隊與裝備仍由 `GameApp` 透過既有遊戲命令、儲存流程與收藏交易處理。造型預覽與面板位置只存於目前頁面的介面狀態；預覽不修改已裝備形態，也不寫入收藏紀錄。角色招募狀態依持有任一造型判定，只有夏日裝的汐音／熾夏也可出戰，原裝仍維持未持有。

## 驗證

`tests/e2e/mobile-layout.spec.ts` 檢查主要控制完整位於視窗內、點擊區域至少 44px、文件沒有水平或垂直溢出，以及詳細面板、鍵盤焦點、切換桌面與手機版的流程。

手機測試尺寸為 320×500、375×548、320×640、375×667、390×844、430×932 CSS 像素；前兩種用來檢查瀏覽器工具列占用空間後的短視窗。另外檢查 768、1024、1440px 寬度切換，並執行既有招募、存檔恢復、自由配點與舊版技能樹回歸測試。

編隊測試另檢查八人總覽、招募及造型數量、預覽不修改存檔、確認裝備後重載、鎖定狀態與角色面板的鍵盤焦點。既有手機回歸包含實際點擊位置未被底部功能列遮住、儲存失敗後重試、重置確認焦點與關閉詳細面板。

這些是 Chromium／WebKit 瀏覽器引擎驗證，實際 iPhone Safari 的工具列、瀏海安全區與觸控手感仍需真機確認。

```sh
E2E_PORT=5174 VALIDATION_OUTPUT_DIR=/tmp/starfall-mobile-validation npm run test:e2e -- tests/e2e/mobile-layout.spec.ts tests/e2e/roster-overview.spec.ts
npm run test:rules
npm run build
```

### 戰鬥聚焦模式

戰鬥主畫面固定一屏，390 × 844 直向畫面約 80% 留給戰場。頂部保留防線血量、倒數、倍速與暫停，底部保留隊長技能、自動施放及構築入口。隊員射程、波次、經驗與機制說明集中在「隊伍／情報」面板；Escape 可收起情報且不暫停戰鬥。

畫布隨容器伸縮，世界座標與戰鬥規則不變，角色立繪補償縱向縮放以保持比例。怪物達 24 隻時，持續弱點標示與血條保留給 Boss、精英及正在蓄力的敵人。Boss 蓄力顯示倒數和防線目標，攻擊光束與防線傷害提示由實際 wall-hit 事件觸發；減少特效設定停用震動和額外火花。
