# 手機遊戲介面更新

本次調整手機顯示與操作方式，戰局內容版本沿用 `0.4.0-dev.1`。

## 操作方式

- 全螢幕遊戲面板，上方顯示遊戲狀態，下方功能列切換作戰、編隊、招募、圖鑑與紀錄。
- 作戰中心按章節切換關卡；編隊一次查看一位角色，出戰名單與出擊操作保持可見。
- 角色、章節、收藏與技能階段可以用左右按鈕切換，也可直接從選單選取。
- 圖鑑、服裝能力、戰鬥報告、敵方對策與完整立繪放進詳細面板。只有面板內容需要捲動，關閉按鈕保持可見。
- 配點一次顯示目前角色、路線與技能階段；點節點預覽，確認後才花點。完整效果與前置條件由「效果／前置」查看。
- 招募與收藏兌換、音效與存檔管理分開切換；招募或兌換完成後直接顯示已保存結果。
- 螢幕較矮時縮減裝飾與立繪預覽，保留主要操作的點擊空間。桌面寬度超過 800px 時恢復完整資訊排列。

## 結構

`mobile-controls.ts` 管理分頁與原生詳細面板；`mobile.ts` 處理首頁、編隊與圖鑑；`mobile-secondary.ts` 處理其他選單；`mobile-combat.ts` 處理戰鬥覆蓋面板；`mobile-notice.ts` 將存檔等通知放入頂部 HUD，保留完整恢復操作。`mobile-game.css` 統一場景、立繪、金色選中狀態與珊瑚色出擊按鈕。這些模組重新安排既有控制項，沿用原本的遊戲命令與儲存流程。頁籤位置只存於目前頁面工作階段，不寫入戰局存檔。

## 驗證

`tests/e2e/mobile-layout.spec.ts` 檢查主要控制完整位於視窗內、點擊區域至少 44px、文件沒有水平或垂直溢出，以及詳細面板、鍵盤焦點、切換桌面與手機版的流程。

手機測試尺寸為 320×500、375×548、320×640、375×667、390×844、430×932 CSS 像素；前兩種用來檢查瀏覽器工具列占用空間後的短視窗。另外檢查 768、1024、1440px 寬度切換，並執行既有招募、存檔恢復、自由配點與舊版技能樹回歸測試。

最終遊戲版型的 Chromium／WebKit 手機回歸共 24 項全數通過，包含實際點擊位置未被底部功能列遮住、儲存失敗後重試、重置確認焦點與關閉詳細面板。規則及存檔測試 285 項通過；建置與型別檢查通過。

這些是 Chromium／WebKit 瀏覽器引擎驗證，實際 iPhone Safari 的工具列、瀏海安全區與觸控手感仍需真機確認。

```sh
E2E_PORT=5174 VALIDATION_OUTPUT_DIR=/tmp/starfall-mobile-validation npm run test:e2e -- tests/e2e/mobile-layout.spec.ts
npm run test:rules
npm run build
```
