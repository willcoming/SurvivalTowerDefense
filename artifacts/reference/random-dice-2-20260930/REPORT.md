## 本專案可採用的方向

1. **點節點先顯示詳情，再確認投入。** 點選顯示選取框、效果與需求；保留現有「暫選 → 確認配置並繼續」規則，讓暫選回饋更明顯。
2. **手機詳情固定在底部。** 可先試底部約 30–35% 高的面板，保留上方樹與所選節點；長說明在面板內閱讀。這是本專案建議，並非《亂數骰子２》目前實作。
3. **直接換選其他節點。** 點另一節點就更新面板，確認按鈕維持位置，減少先關閉再點選的操作。
4. **圖示與命中區分開設計。** 以 Apple 按鈕一般至少 44×44 pt 的命中區指引作原生參考；Web 專案可先採至少 44×44 CSS px、主要節點 48–56 CSS px，再真機驗證。命中區彼此避免重疊。[Apple 按鈕設計指引](https://developer.apple.com/design/human-interface-guidelines/buttons?changes=latest_1)
5. **具體列出鎖定原因。** 顯示缺少的前置與點數，附定位前置入口；狀態同時使用文字／圖示，避免只靠顏色。
6. **工具不要蓋住節點。** 預留樹視口，加入回起點／全覽；僅在節點被面板遮住時平移，避免每次選取都大幅移動。
7. **樹上短資訊，面板放細節。** 手機 Web 說明文字可先以 14–16 CSS px、標題 16–18 CSS px 試作，再按真機閱讀狀況調整；上述為建議起始值。
