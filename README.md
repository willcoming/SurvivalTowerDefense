# 星骸防線：黎明反攻

單人手機直向網頁塔防。近未來地球遭外星入侵，八位成年角色以改良的外星科技武器展開反攻。自由選擇最多五人出戰，靠局內改造、隊伍分工與隊長技能完成六至八分鐘的防守。

免登入；初始六位角色原裝免費開放。關卡與挑戰首通提供免費招募機會，獎池包含八套夏日裝與兩位新角色原裝。重打不發招募資源；沒有付費抽獎、永久等級、體力或每日任務。

目前新局為 **0.4.0-dev.1 星際夏日招募與章節版**。[線上遊玩](https://willcoming.github.io/SurvivalTowerDefense/) · [公開原始碼](https://github.com/willcoming/SurvivalTowerDefense)。玩法、執行狀態與驗證結果見 [文件總覽](docs/README.md)。

## 本機啟動

需求：Node.js 22.12 以上（實測 22.22.3）及 npm。從本專案資料夾執行：

```sh
npm ci --no-audit --no-fund
npm run build
npm run preview
```

電腦開啟 [本機遊戲](http://localhost:5173/)。手機連上同一個 Wi-Fi，再開啟終端輸出的 `Network` 網址；區網 IP 會隨網路改變，請以當次輸出為準。主機需保持開機且 preview 仍在執行。

開發時使用 `npm run dev`。dev 與 preview 都固定 **5173** 且拒絕自動換埠，只能同時啟動其中一個；先在原終端按 Ctrl+C，再換另一個命令。不要直接雙擊 `index.html`。`dist/` 是建置後的靜態網站；已發布至 [GitHub Pages](https://willcoming.github.io/SurvivalTowerDefense/)。

## 操作

1. 選擇關卡並查看敵人情報；在編隊頁加入 1–5 人，指定一名隊長；可先在角色圖鑑查看完整技能樹。
2. 點擊「開始行動」。武器自動索敵；點擊隊長技能按鈕施放技能，留意敵人的蓄力文字與紅色預警。
3. 每累積 60 經驗取得 2 點，自動暫停並開啟完整技能樹。點節點預覽，再按「確認取得」花費 1 點；兩點用完後繼續，可暫存離開。本局不洗點。
4. 每人有 2–3 條不對稱樹，共 174 個角色節點及 12 個共用節點，可跨樹混搭。同樹投入 4 點並滿足前置後，第 5 點可取得終極；全局 24 點、每人一終極、全隊最多三個。
5. 擊敗六分鐘時登場的 Boss 並清除剩餘敵人。八分鐘仍未完成或防線 HP 歸零則失敗。

戰鬥右上角的速度按鈕依序切換 **1× → 2× → 3× → 1×**，選擇會自動記住。敵我攻擊、移動、冷卻、波次與倒數同步加速；配點與暫停時完全停止。六至八分鐘指有效戰鬥時間，全程 3× 約需兩分至兩分四十秒，另加配點及暫停時間。

初始六人原裝沿用瞄準、射擊與後座逐格動作；十個新增形態有獨立立繪，在戰場以呼吸／後座位移呈現，不是十套新逐格動畫。29 個終極以角色素材與程序特效呈現機制。隊長特寫持續約 1.2 秒，專屬戰場特效持續約 1.5 秒，戰鬥持續進行；3× 不縮短演出，預警保持最高圖層，密集戰鬥會自動減少裝飾特效。

新戰局加入近／中／遠射程：雷娜、米菈為近程，璃音、希雅為中程，凜月、芙蕾為遠程。點擊下方角色頭像可切換射程覆蓋，再點一次關閉；目標尚未進入射程時會顯示等待。爆炸邊界對應實際作用範圍，敵人身上的火焰、緩速環、暈眩符號與曝露框跟隨實際狀態；持續傷害按裝備形態顯示屬性顏色與名稱，合併顯示已造成的傷害。

三位 Boss 各有警示、傳送門、現身與名稱演出，固定約 **1.5 秒現實時間**，期間戰鬥、倒數與冷卻全部暫停，之後自動恢復。3× 不縮短出場時間；暫停或重新載入能接續剩餘演出。詳見 [射程與戰鬥可讀性更新](docs/COMBAT_READABILITY_UPDATE.md)。

技能按鈕旁的「自動施放」可隨時開關，也可在設定中調整。隊長開局先冷卻 45 或 50 秒有效戰鬥時間，手動及自動均相同。開啟後，場上有敵人且冷卻完成時會自動使用隊長技能；仍沿用原本索敵、傷害與冷卻。設定保存在目前瀏覽器，初始關閉；暫停、配點、背景暫停與禁用技能挑戰均不會自動施放。

八種敵人與三隻 Boss 新增待機、六格移動、蓄力和出手動作。3× 下步態有可讀性上限，實際移動與攻擊時序仍同步加速。

桌面可按空白鍵施放技能、Escape 暫停；所有選項也可用鍵盤 Tab 操作。手機切背景或橫放時暫停，返回後需確認繼續。暫停／配點時間不計入有效戰鬥時間。

## 星際夏日招募

主線 12 關＋夏日支線 3 關各首通 1 張券；主線每關另有四人、禁隊長技能、兩終極三項挑戰，各首次成功 25 點。100 點可抽一次，總收入相當於 24 抽，保底後未使用資源保留；完成全部 51 個目標直接補齊本期收藏。

每個獎項 10%。抽到重複形態轉 10 共鳴碎片，100 碎片可指定尚未持有形態；全收集後停止扣款。新角色原裝與夏日裝分開，先得到夏日裝即可出戰，不會同時得到原裝。請在編隊／圖鑑選擇形態；戰鬥中不能換裝。

每種敵人有固定弱點；玩家攻擊命中對應弱點為 1.5 倍，其他為 1 倍，沒有抗性減傷。角色的普通攻擊、隊長傷害及衍生傷害都採用裝備形態屬性；不增加控場時間或盾量。服裝採優點／代價互換，不疊加收藏能力。

## 本地存檔

進度與完整戰局快照保存在 **目前瀏覽器、目前網址來源的 IndexedDB**。每五秒現實時間及取得技能、波次、暫停、切換速度等關鍵操作保存。重開頁面可繼續最近成功保存點，包含敵人、護盾、燃燒、彈體、技能冷卻、已配點數、剩餘技能點與固定敵情。缺少速度偏好的舊存檔自動補上 1×，不需重置戰局。

重新載入最新網站後，新開一局採用 `0.4.0-dev.1` 的自由技能樹與單向弱點規則，並提前展示固定種子的敵群變體與波次事件。`0.3.0-dev.1` 舊局保留原六人、150 節點與傷害規則。`0.2.0-dev.1` 舊局保留原 70 節點及三選一。`0.1.0-dev.2` 舊局沿用全域索敵與原 Boss 時序；`0.1.0-dev.3` 舊局沿用 A/B 改造、射程及 Boss 登場規則。舊局配點不強制轉換，關卡進度及偏好設定均保留。

技能樹按鈕也可在戰鬥中打開，查看時暫停；關閉後回到原本的戰鬥／暫停狀態。完整設計見 [自由技能樹規格](docs/FREE_SKILLS.md)、[186 節點表](docs/FREE_SKILL_NODES.md)，研究結果見 [驗證報告](docs/FREE_SKILL_VALIDATION.md)。

- localhost、區網 IP、不同埠或不同瀏覽器是不同存檔；這不是雲端同步。
- 清除瀏覽器網站資料會清除紀錄；私密瀏覽可能只暫時保存。
- 多分頁衝突會提示重新讀取，舊頁不能覆寫新進度。
- 損壞／不相容紀錄會保留並顯示恢復選項，不會自動重置。設定中的重置需要明確確認。
- 瀏覽器拒絕儲存時可明確選擇暫存遊玩；畫面會說明尚未保存。

## 檢查與測試

```sh
npm run typecheck
npm run test:rules
npm run test:simulation
npm run test:e2e
npm run build
```

規則與存檔測試使用 Vitest、fake-indexeddb；主線驗證以初始角色原裝逐 tick 模擬 51 個目標 × 3 組種子，共 153 局，另驗證十種獎池形態最終關及第 7 點存檔恢復。`npm run test:simulation:free` 比較 29 個終極、兩種投入、前三關與十個固定種子（`-- --quick` 使用一組種子）；`npm run test:tree-matchups` 另做 200 個固定敵群探針。`npm run test:simulation:v2` 保留 0.2 版本的 840 局策略。舊 A/B 平衡策略可用 `npm run test:simulation:legacy` 重現。瀏覽器測試使用開發模式的限定測試入口，預設 `npm run test:e2e` 會在 5173 啟動 dev；若 preview 正在執行，可用 `E2E_PORT=5174 npm run test:e2e`，以獨立埠與測試瀏覽器執行。首次需執行 `npx playwright install chromium webkit` 取得測試瀏覽器。測試入口不會出現在正式 build。

`npm run test:performance` 量測桌面純模擬壓力；build 後 `npm run test:assets` 檢查素材清單及容量。切換至正式 preview 後，可用 `npm run test:production` 在限制頻寬的 Chromium 中驗證切換 3×、真實等待升級、保存與重載，不使用開發測試入口。

0.4 驗證與已知限制見 [招募／戰鬥交付](docs/COLLECTION_UPDATE.md)。0.3 的 1,500 場平衡與 147 個瀏覽器案例屬於歷史結果，不作為本版新增內容的通過證明。

## Git 版本紀錄

專案沿用既有本地 Git 歷史，**`v0.3.0-dev.1`** 標記自由技能樹可玩版。原始碼、測試、文件、遊戲素材及版本化驗證證據納入版控；依賴、建置輸出、暫存測試檔與本地環境設定由 `.gitignore` 排除。公開 GitHub 遠端已建立，使用 `npm run deploy:pages` 發布；設定、版本比對與上線結果見 [部署紀錄](docs/GITHUB_PAGES.md)。

```sh
git status
git log --oneline -5
git show v0.3.0-dev.1 --stat
```

後續功能可使用 `codex/` 前綴建立分支，將相關程式、測試與文件一併提交。Git 追蹤專案檔案；瀏覽器 IndexedDB 的遊戲進度仍依本地存檔規則保存。

## 程式結構

`src/sim/`：30 Hz、無渲染依賴的確定性戰鬥；`src/data/`：角色、路線、敵人及關卡；`src/storage/`：有序交易與 revision 衝突控制；`src/ui/`：繁體中文操作流程；`src/game/`：Phaser 畫面與原創合成音訊；`public/assets/`：本機美術素材。

這份交付不代表已完成真實手機效能或真人趣味性測試。實際裝置與真人驗證記錄會在工程交付報告中分開列示。
